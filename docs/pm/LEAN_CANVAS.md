# リーンキャンバス: AuraNews

| 要素                  | 内容                                                                                                                                                        |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. 顧客セグメント** | - 忙しいが最新動向は追いたいビジネスパーソン<br>- 情報収集の時間が取れない人<br>- [仮説] 興味分野がニッチで既存ニュースアプリに不満がある人                 |
| **2. 課題**           | - ニュースが多すぎて本当に必要な情報が埋もれる<br>- 自分で検索・選別する時間や気力がない<br>- 同じようなニュースばかり表示される                            |
| **3. 独自価値提案**   | - 興味のある最新ニュースだけを、朝・昼・夕の1日3回、短時間で読める「自分だけの手軽な新聞」として届ける                                                      |
| **4. 解決策**         | - 選択したカテゴリに基づき、24時間以内の話題性が高い記事を厳選<br>- 重複を排除し、各記事に1〜3行の要約と選定理由を付与<br>- 朝・昼・夕各5〜10本の固定枠配信 |
| **5. チャネル**       | - アプリストア（App Store / Google Play）検索<br>- [仮説] SNS（Xなど）での「今日の自分新聞」シェアによる口コミ<br>- ビジネス系メディアへのプレスリリース    |
| **6. 収益の流れ**     | - [仮説] 無料枠＋プレミアム機能（カテゴリ数無制限、過去記事無制限保存など）のサブスクリプション<br>- [仮説] 一部枠にターゲット広告を配信                    |
| **7. コスト構造**     | - API利用・サーバー運用費（ニュース取得、要約生成AI）<br>- アプリ開発・保守費<br>- カスタマーサポート費                                                     |
| **8. 主要指標**       | - 継続利用率（毎日朝刊などを開くか）<br>- 記事ごとのフィードバック率（保存・興味なしのタップ率）<br>- 記事の詳細閲覧率                                      |
| **9. 競合優位性**     | - [仮説] ニュースを選ばない「新聞形式」×「AI要約＆選定理由表示」による究極のタイパ体験<br>- シンプルなUIで離脱を防ぐ初期体験                                |

## 最も危険な前提（トップ3）

1. ユーザーは「ニュースが厳選（5〜10本）されていれば、物足りなさより手軽さを評価する」という前提
2. カテゴリ選択と自動収集のロジックだけで、ユーザーが満足する品質のニュース選別が可能という前提
3. ニュース要約と選定理由の自動化（AI等）コストが、収益を圧迫しないという前提
