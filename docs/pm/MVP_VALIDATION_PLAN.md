# MVP Validation Plan

## 1. 仮説の定義

**仮説:** 忙しいビジネスパーソンは、情報量が多いことよりも、「1日数本に厳選・要約されたニュースだけで済ませられるタイパ体験」にお金を払う（または継続利用する）。

## 2. 検証プラン

### 実験方法候補（実装コスト順）

1. **LP検証（Fake Door / プレオーダー）**
   - **内容:** アプリのコンセプト（1日3回、厳選要約ニュースのみ）を説明したLPを作成し、事前登録（メールアドレス入力）や「購入する」ボタンを置く。
2. **手動配信検証（コンシェルジュMVP）**
   - **内容:** 事前登録した数名に対し、毎朝・昼・夕に手動で選定・要約したニュース5本をLINEやメールで送信し、フィードバックを得る。
3. **プロトタイプアプリ（最小実装）**
   - **内容:** カテゴリの選択と、AIで自動生成された固定枠ニュースを表示するだけの最小限のアプリまたはWebアプリ。

### 推奨実験: 学びが最大で工数が最小の実験

**【コンシェルジュMVP（LINEやメールでの手動配信検証）】**
アプリを作らなくても、ターゲティングした数名に対して「本当に厳選・要約に価値を感じるか」「毎日読むか」の熱量を直接検証でき、フィードバックループが最も速い。

---

## 3. 実験の詳細設計（コンシェルジュMVPの場合）

- **対象:** 身近なビジネスパーソンやX等で募集したターゲットユーザー（5〜10名程度）
- **計測指標:**
  - **入力指標:** メッセージやメールの開封率
  - **結果指標:** 継続購読意向（1週間後のアンケートで「課金してでも続けたいか？」）、日々の定性フィードバック（「この記事はいらない」「ちょうどよい」など）
- **成功閾値:** 参加者の50%以上が「満足しており、手間が減った」と回答し、かつ「課金しても良い/アプリがあれば使いたい」と答えること。
- **期間:** 1週間（平日5日間）
- **停止条件:** 参加者の過半数が3日連続で開封しない、または「やっぱり自分で好きなニュースを探したい」という反応が多数を占めた場合。
- **次の意思決定:**
  - 成功 → プロトタイプアプリ（最小実装）の開発に移行。
  - 失敗 → 仮説の修正（トピックが良くないのか、タイパを求めていないのか定性ヒアリング）。
